🔬 DOSSIER TECHNIQUE D'ARCHITECTURE & MÉTIER

Plateforme WiQayati (وقايتي)

Système national tunisien de dépistage précoce, de stratification du risque et de coordination préventive du diabète de type 2. Document de référence couvrant le backend Django, le portail web multi-rôles, l'application mobile Expo et le contrat formel du pipeline de dépistage.

Version Système : 1.0.0 Production
Contrat Moteur Risque : Figé v1.0 (2026-09-24)
Standard Données : HL7 FHIR R4
Pivot Patient : Identifiant National de Santé (INS)

1. Vision & Cadre Métier

En Tunisie, le diabète de type 2 représente une urgence sanitaire majeure, touchant près de 15% à 20% de la population adulte avec une proportion alarmante de cas non diagnostiqués. WiQayati a été conçue pour inverser la courbe épidémiologique en déployant une démarche proactive de santé publique.

Identification Unique
Pivot INS
Dossier unique et immuable par citoyen, interdisant toute duplication de données.
Scoring Clinique
FINDRISC Adapté
14 variables médicales et comportementales scorées de 0 à 100 points.
Validation Obligatoire
CarePlan Médical
Génération automatique en brouillon, obligatoirement validé par un nutritionniste.
Règle d'or de l'application mobile
L'application mobile citoyenne demeure principalement un outil de dépistage et de suivi médicalisé. Le module de « Suivi quotidien » est une extension secondaire rattachée au plan de soins validé par le soignant, et ne doit en aucun cas se substituer à une application fitness autonome.

3. Le Contrat du Pipeline de Dépistage

Le dépistage de diabète est un pipeline transactionnel atomique (`@transaction.atomic`). Aucun état incohérent n'est toléré : la création du patient, l'enregistrement des 14 réponses, l'évaluation du score, la création du plan brouillon et l'ordonnancement dans la file nutritionniste s'exécutent en une seule transaction isolée.

Les 14 Variables Obligatoires du Formulaire

# Variable JSON Type & Bornes Pondération Clinique Description Médicale
1 age int (18 – 120) +15 pts si ≥ 45 ans L'âge est le principal inducteur non modifiable d'insulinorésistance.
2 genre "M", "F", "AUTRE" Clinique Conditionne l'évaluation du diabète gestationnel et les seuils de tour de taille.
3 imc float (10.0 – 80.0) +20 pts (≥30) / +10 pts (25-30) Indice de Masse Corporelle (kg/m²). Surpoids ou obésité morbide.
4 tour_taille_cm float (40.0 – 200.0) Clinique Adiposité viscérale abdominale hautement athérogène.
5 antecedents_familiaux_diabete boolean +20 pts si true Présence de diabète au premier degré (père, mère, fratrie).
6 hypertension_diagnostiquee boolean +15 pts si true HTA avérée ≥ 140/90 mmHg ou traitement antihypertenseur en cours.
7 niveau_activite_physique "FAIBLE", "MODERE", "ELEVE" +10 pts si "FAIBLE" Sédentarité (< 30 minutes de marche ou équivalent par jour).
8 qualite_alimentation "MAUVAISE", "MOYENNE", "BONNE" +5 pts si "MAUVAISE" Carence en fibres, faible consommation de légumes, excès de sucres raffinés.
9 statut_tabagisme "JAMAIS", "EX_FUMEUR", "FUMEUR_ACTUEL" +5 pts si "FUMEUR_ACTUEL" Aggravateur direct de stress oxydatif et d'atteinte microvasculaire.
10 glycemie_jeun_connue boolean Indicateur Signale si le sujet a déjà bénéficié d'un contrôle biologique récent.
11 glycemie_jeun_mmol float ou null Biologique Valeur de glycémie à jeun en mmol/L (facultatif si non dosée).
12 diabete_gestationnel_antecedent boolean +15 pts si true Antécédent d'hyperglycémie durant une grossesse (femmes).
13 medicaments_corticoides boolean Iatrogène Prise chronique de corticoïdes induisant une résistance insulinique.
14 acanthosis_nigricans boolean +10 pts si true Hyperpigmentation cutanée des plis (signe direct d'hyperinsulinisme sévère).

4. Algorithme de Calcul & Stratification

Le score global est borné dans l'intervalle $[0, 100]$. Il est découpé en 3 classes de risque clinique qui déterminent automatiquement la priorité de prise en charge et l'échéance de réévaluation préventive :

Score < 30 pts
Risque FAIBLE
Priorité File : ROUTINE
Échéance Réévaluation : 12 mois
Action : Maintien des saines habitudes de vie.
30 ≤ Score < 60 pts
Risque INTERMÉDIAIRE
Priorité File : URGENT
Échéance Réévaluation : 12 mois
Action : Rééquilibrage alimentaire et activité ciblée.
Score ≥ 60 pts
Risque ÉLEVÉ
Priorité File : STAT (Immédiat)
Échéance Réévaluation : 6 mois adaptatif
Action : Prise en charge multidisciplinaire & bilan biologique.

6. Workflow Plan de Soin & File Nutritionniste

Un patient dépisté ne reçoit jamais directement un protocole non supervisé. Le module apps.care_plan et la file apps.nutritionist_queue encadrent la validation clinique :

stateDiagram-v2 [*] --> BROUILLON : Soumission Dépistage (Génération auto) BROUILLON --> DEMANDE : Insertion File Nutritionniste DEMANDE --> EN_COURS : Prise en charge par le Nutritionniste EN_COURS --> VALIDE : Validation avec ou sans ajustement EN_COURS --> REJETE : Rejet motivé (ex: incohérence médicale) VALIDE --> [*] : Publication vers l'App Mobile REJETE --> [*] : Clôture du dossier
Garantie d'Indépendance & Rôle du Praticien
Le nutritionniste référent dispose des droits complets pour :
  • Modifier ou ajouter des objectifs nutritionnels ciblés (ex: réduction des glucides simples, apport hydrique).
  • Ajuster la fréquence (séances/semaine) et la durée (minutes/séance) de l'activité physique adaptée.
  • Rédiger des observations cliniques personnalisées dans notes_nutritionniste.

7. Architecture Backend Core (Django REST Framework)

Le backend est structuré en 7 applications autonomes dans backend/apps/ :

Application Modèles Principaux Responsabilité Métier
apps.screening ProfilPatient, ReponseScreening Pivot INS national, capture des 14 variables du formulaire, déduplication stricte.
apps.risk_engine ResultatEvaluationRisque Client Moteur de Risque, stub déterministe v1.0, failover transparent vers IA distante.
apps.care_plan PlanSoin CarePlan FHIR, stockage JSON des objectifs, statut de cycle de vie (BROUILLON / VALIDE).
apps.nutritionist_queue TacheNutritionniste Ordonnancement des validations médicales (STAT, URGENT, ROUTINE), métriques de prise en charge.
apps.accounts Utilisateur Authentification JWT, gestion des rôles RBAC, liaison citoyen par INS.
apps.fhir_bridge Passerelle Service Transformation bidirectionnelle vers les ressources HL7 FHIR R4 et synchronisation HAPI.
apps.audit AuditLog Piste d'audit médico-légale immuable (qui a consulté/modifié quel dossier et quand).

9. Architecture Mobile (Expo / React Native)

L'application mobile citoyenne (mobile/) a été pensée pour un usage quotidien simple, intuitif et rassurant :

Écran d'Accueil
WelcomeScreen
Présentation épurée de la mission et des garanties de santé avant saisie du code INS.
Suivi Quotidien
Offline-First
Persistance locale AsyncStorage indexée par INS et synchronisation asynchrone sans blocage.
Seuil Adaptatif
6m / 12m
Le composant StatutDernierBilan adapte automatiquement le rappel de dépistage au profil de risque.

Organisation des 5 Onglets Natifs

  • Dossier (index) : Fiche identité INS, Statut du dernier bilan avec CTA adaptatif, historique chronologique des évaluations.
  • Mon Plan (plan) : Recommandations nutritionnelles et programme d'activité physique validés par le nutritionniste, avec encart de progression du jour.
  • Évaluation (autoeval) : Formulaire FINDRISC interactif en 3 étapes avec restitution immédiate du niveau de risque calculé.
  • Suivi (suivi) : Mini-calendrier rétrospectif 7 jours, coches individuelles par objectif nutritionnel (`objectifs_coches: number[]`) et validation de l'activité.
  • Alertes (notifications) : Notifications de rappel avec filtres par puces (🔬 Dépistage vs 📊 Suivi quotidien).

10. Interopérabilité HL7 FHIR R4

WiQayati garantit une compatibilité native avec les systèmes hospitaliers et dossiers médicaux partagés nationaux via le standard international HL7 FHIR R4 :

Modèle WiQayati Ressource FHIR R4 Mappage & Identifiants Clés
ProfilPatient Patient identifier[system="urn:ins:tn"].value = ins, nom, prénom, date de naissance, genre.
ReponseScreening QuestionnaireResponse item[linkId].answer pour chacune des 14 variables du formulaire.
ResultatEvaluationRisque RiskAssessment / Observation Score global FINDRISC et facteurs de risque contributifs codés en LOINC / SNOMED-CT.
PlanSoin CarePlan Prescription diététique et programme d'activité physique avec statut de validation médicale.

11. Sécurité, Rôles RBAC & Audit Trail

Rôle Système Permissions & Périmètre d'Action
CITOYEN Accès restreint à son dossier personnel par son INS + PIN. Consultation de ses scores et suivi de son plan actif.
AGENT_CAMPAGNE Recherche de patients par INS, création de fiches, soumission de dépistages dans le cadre de campagnes mobiles.
AGENT_SOINS_PRIMAIRES Saisie de dépistages au sein des centres de santé de base (CSB), consultation de l'historique médical complet.
NUTRITIONNISTE Dépouillement de la file de travail, ajustement des objectifs alimentaires et validation finale des plans de soins.
MEDECIN Supervision clinique, réévaluation de dossiers complexes, accès intégral aux observations et prescriptions.
ADMIN_MINISTERE Accès exclusif aux agrégats de santé publique, cohortes anonymisées et indicateurs de performance épidémiologique.

12. Guide de Démarrage & Commandes d'Exploitation

Commandes canoniques pour exécuter l'ensemble de la pile technique en environnement de développement ou de test :

1. Démarrage du Backend Core (Django)

cd backend
python manage.py migrate
python manage.py runserver 0.0.0.0:8000

2. Démarrage de la Passerelle Proxy Node.js (Port 8008)

node backend_proxy.js

3. Démarrage du Portail Web (React / Vite)

cd frontend
npm install
npm run dev   # Accessible sur http://localhost:5173

4. Démarrage de l'Application Mobile (Expo / React Native)

cd mobile
npm install
npx expo start --web   # Ou scan du QR code avec Expo Go

5. Validation Statique TypeScript

cd mobile
npx tsc --noEmit   # Valide 0 erreurs sur l'ensemble des écrans et hooks
